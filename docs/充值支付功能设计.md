# 充值 / 支付功能设计文档

> ⚠️ **本文档已作废（2026-11-01）**
>
> 这是 1.0 时代基于「预存余额」的支付设计。后续推翻了余额模型，改为**押金制**——余额在用户没钱时会导致逾期扣款失败，商户承担坏账。
>
> 请阅读 `共享图书借阅平台设计文档.md`。本文档仅作历史记录保留，其中「充值」「余额扣款」相关设计已被废弃。

> 项目：图书管理系统（1.0）
> 技术栈：Spring Boot 2.7 + MyBatis-Plus + MySQL 8.0 + Vue2/Vue3 + Element Plus
> 文档目标：把「读者自助充值」做成一套完整、可对账、可扩展真实支付渠道的资金链路

---

## 一、现状盘点

### 已经具备（可直接复用，不要重写）

| 能力 | 位置 | 说明 |
|---|---|---|
| 余额字段 | `user.balance` DECIMAL(10,2) | 精度正确，禁止改 double |
| 原子加钱 | `UserMapper.addBalance(id, amount)` | `UPDATE ... SET balance = balance + ?` |
| 原子扣钱 | `UserMapper.deductBalance(id, amount)` | 带 `balance >= ?` 条件，余额永不为负 |
| 行锁 | `UserMapper.lockById(userId)` | `SELECT ... FOR UPDATE`，串行化并发校验 |
| 管理员充值 | `POST /user/reader/{id}/recharge` | 线下收现金 → 后台改数字 |
| 消费出口 | `PurchaseServiceImpl.buy`、`BorrowServiceImpl.settleOverdue/processOverdue` | 已走余额扣减 |

### 缺口（本文档要解决的）

1. 读者**不能自助充值**，只能找管理员
2. **没有充值订单**，钱进来了无法追溯来源
3. **没有资金流水**，余额对不上账时无从查证
4. 没有超时关单、掉单补偿、对账机制
5. 购买/补缴扣款**不写流水**，只有余额变化，无法生成账单

### 关键结论

`user.balance` 只是一个**数字快照**，不是账本。真正的账是流水表。
答辩被问「怎么保证钱没算错」，正确答案是：**每一笔资金变动都有流水，余额 = 流水累计，随时可校验**。

## 二、路线决策

### 三条路线对比

| 维度 | 模拟支付 | 支付宝沙箱 | 微信/支付宝正式商户 |
|---|---|---|---|
| 资金真实 | 否 | 否（沙箱虚拟余额） | 是 |
| 技术链路真实度 | 自行实现，可做到等同 | 100%（真 SDK + RSA2 签名 + 真回调） | 100% |
| 资质门槛 | 无 | 支付宝实名认证 | 营业执照 + 商户号 + ICP 备案域名 |
| 个人能否开通 | 能 | 能 | **不能** |
| 开发量 | 1～2 天 | 2～4 天 | 2～4 天 + 审核周期 |
| 适合场景 | 课设/毕设交付 | 简历亮点、真实支付经验 | 商业上线 |

### 决策：模拟支付 + 渠道抽象接口

理由：

1. 微信支付正式环境对个人开发者**完全关闭**，没有营业执照拿不到 mchid，这不是技术问题而是资质问题。
2. 支付宝沙箱资金是虚拟的，本质也不是"真收钱"，但换来了真实 SDK 经验。
3. 业务链路（订单、幂等、回调、验签、对账、关单）**与渠道无关**，先做扎实，将来接任何渠道都不用改。

**核心设计：把渠道差异收敛到一个接口后面。**

```
RechargeService（业务逻辑，与渠道无关）
        │ 依赖
        ▼
   PayChannel（接口）
   ├── MockPayChannel        ← 本期实现
   ├── AlipaySandboxChannel  ← 将来新增
   └── WechatNativeChannel   ← 将来新增
```

将来接支付宝，只新增一个实现类 + 改一行配置，`RechargeService` 完全不动。

## 三、数据库设计

新增两张表。DDL 风格与 `sql/init.sql` 保持一致。

```sql
-- --------------------------------------------
-- 8. recharge_order 充值订单表
-- --------------------------------------------
CREATE TABLE `recharge_order` (
  `id`               BIGINT        NOT NULL AUTO_INCREMENT COMMENT '主键',
  `order_no`         VARCHAR(32)   NOT NULL COMMENT '充值订单号（业务幂等键）',
  `user_id`          BIGINT        NOT NULL COMMENT '充值用户id',
  `amount`           DECIMAL(10,2) NOT NULL COMMENT '充值金额（以服务端为准）',
  `pay_channel`      TINYINT       NOT NULL DEFAULT 3 COMMENT '支付渠道：1微信 2支付宝 3模拟',
  `status`           TINYINT       NOT NULL DEFAULT 0 COMMENT '状态：0待支付 1已支付 2已关闭 3已退款',
  `channel_trade_no` VARCHAR(64)   DEFAULT NULL COMMENT '渠道交易号（微信/支付宝返回）',
  `pay_time`         DATETIME      DEFAULT NULL COMMENT '支付完成时间',
  `expire_time`      DATETIME      NOT NULL COMMENT '订单失效时间（默认下单+15分钟）',
  `remark`           VARCHAR(255)  DEFAULT NULL COMMENT '备注',
  `is_delete`        TINYINT       NOT NULL DEFAULT 0 COMMENT '逻辑删除',
  `create_time`      DATETIME      DEFAULT NULL COMMENT '下单时间',
  `update_time`      DATETIME      DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_order_no` (`order_no`),
  KEY `idx_user_status` (`user_id`, `status`),
  KEY `idx_status_expire` (`status`, `expire_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='充值订单表';

-- --------------------------------------------
-- 9. payment_flow 资金流水表（账本，不可删改）
-- --------------------------------------------
CREATE TABLE `payment_flow` (
  `id`            BIGINT        NOT NULL AUTO_INCREMENT COMMENT '主键',
  `user_id`       BIGINT        NOT NULL COMMENT '用户id',
  `biz_type`      TINYINT       NOT NULL COMMENT '业务类型：1充值 2购书 3逾期补缴 4退款 5管理员调账',
  `biz_id`        BIGINT        DEFAULT NULL COMMENT '关联业务id（充值订单id/购买订单id/借阅id）',
  `biz_no`        VARCHAR(32)   DEFAULT NULL COMMENT '关联业务单号（冗余，便于对账展示）',
  `direction`     TINYINT       NOT NULL COMMENT '资金方向：1收入 2支出',
  `amount`        DECIMAL(10,2) NOT NULL COMMENT '变动金额（正数）',
  `balance_after` DECIMAL(10,2) NOT NULL COMMENT '变动后余额',
  `remark`        VARCHAR(255)  DEFAULT NULL COMMENT '备注',
  `create_time`   DATETIME      DEFAULT NULL COMMENT '发生时间',
  PRIMARY KEY (`id`),
  KEY `idx_user_time` (`user_id`, `create_time`),
  KEY `idx_biz` (`biz_type`, `biz_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='资金流水表';
```

### 设计要点

1. **流水表没有 `is_delete`**。账本只能追加，不能删。退款用一条反向流水冲正，而不是删原记录。
2. **`order_no` 加唯一索引**。这是幂等的最后一道防线，重复插入直接被数据库拒绝。
3. **`amount` 以服务端为准**。前端只传档位（10/50/100/200/500），服务端查出对应金额写库，绝不接受前端传的金额直接入库。
4. **`balance_after` 是快照**。用于快速核对，不必每次重算全部流水。

## 五、核心流程

```
读者选档位 → 创建本地订单(status=0) → 调渠道取二维码 → 展示二维码
                                                          ↓
                                              读者扫码付款（15分钟有效）
                                                          ↓
                                                  渠道异步回调 notify
                                                          ↓
                                                    验签 + 主动查单
                                                          ↓
                        幂等闸门：UPDATE ... WHERE status=0  → 影响行数=1 才继续
                                                          ↓
                              同一事务：加余额 + 写流水 + 订单置已支付
                                                          ↓
                            前端轮询 /recharge/status 到账 → 刷新余额
```

### 三个必须踩对的坑

**坑 1：回调接口被 JWT 拦截器拦死**

渠道服务器不会带你的 `Authorization` 头。必须改 `WebConfig`：

```java
registry.addInterceptor(authInterceptor)
        .addPathPatterns("/**")
        .excludePathPatterns(
                "/auth/login",
                "/auth/register",
                "/uploads/**",
                "/error",
                "/recharge/notify/**"   // 新增：渠道回调不需要登录态
        );
```

`adminInterceptor` 同样要加这条，否则管理员拦截器也会挡住。

**坑 2：回调返回格式不对，渠道以为失败反复重推**

- 支付宝要求返回**纯文本** `success`，返回 JSON 会被判失败，重推 8 次（间隔递增）
- 微信要求返回 `{"code":"SUCCESS","message":"成功"}`
- 处理成功必须返回正确格式，**处理失败也要返回 success**（避免无意义重推），改为记录告警 + 靠定时任务查单补偿

**坑 3：用 `if (order.getStatus() == 0)` 做幂等**

这是无效的。两个回调线程可以同时读到 status=0。必须靠 SQL 条件更新：

```java
// 影响行数 == 1 才说明本次抢到了处理权，其余线程直接返回成功
int updated = rechargeOrderMapper.markPaid(orderNo, channelTradeNo, now);
if (updated == 0) {
    return; // 已处理过，幂等返回
}
```

### 6.2 支付渠道接口（`pay/PayChannel.java`）

```java
package com.library.pay;

import com.library.entity.RechargeOrder;

/**
 * 支付渠道抽象。
 * 新增渠道只需实现本接口 + 在配置里切换，业务代码零改动。
 */
public interface PayChannel {

    /** 渠道标识，对应 Constants.PAY_CHANNEL_* */
    int channelCode();

    /**
     * 向渠道下单，返回二维码内容或支付跳转链接。
     * 真实渠道在此处调用微信/支付宝 SDK，模拟渠道返回本地支付页地址。
     */
    String createPay(RechargeOrder order);

    /**
     * 校验渠道回调签名。模拟渠道用 HMAC，真实渠道用 RSA2 / APIv3。
     * @return 签名是否有效
     */
    boolean verifySign(java.util.Map<String, String> params);

    /**
     * 主动向渠道查单，用于回调丢失后的补偿。
     * @return 渠道侧是否已支付成功
     */
    boolean queryPaid(String orderNo);
}
```

### 6.3 模拟渠道实现（`pay/MockPayChannel.java`）

```java
package com.library.pay;

import com.library.common.Constants;
import com.library.entity.RechargeOrder;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.util.Map;

/**
 * 模拟支付渠道。
 * 走完整链路：生成支付页 → 前端点"我已支付" → 回调 → HMAC 验签 → 幂等入账。
 * 与真实渠道的唯一差异是"钱从哪来"，代码路径完全一致。
 */
@Component
public class MockPayChannel implements PayChannel {

    @Value("${library.pay.mock.secret}")
    private String secret;

    @Value("${library.pay.mock.page-url}")
    private String pageUrl;

    @Override
    public int channelCode() {
        return Constants.PAY_CHANNEL_MOCK;
    }

    @Override
    public String createPay(RechargeOrder order) {
        // 前端拿到该地址后渲染二维码/直接跳转模拟收银台
        return pageUrl + "?orderNo=" + order.getOrderNo() + "&amount=" + order.getAmount();
    }

    @Override
    public boolean verifySign(Map<String, String> params) {
        String orderNo = params.get("orderNo");
        String amount = params.get("amount");
        String sign = params.get("sign");
        if (orderNo == null || amount == null || sign == null) {
            return false;
        }
        return signOf(orderNo + amount).equalsIgnoreCase(sign);
    }

    /** HMAC-SHA256，模拟真实渠道的签名机制 */
    public String signOf(String raw) {
        try {
            Mac mac = Mac.getInstance("HmacSHA256");
            mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
            byte[] bytes = mac.doFinal(raw.getBytes(StandardCharsets.UTF_8));
            StringBuilder sb = new StringBuilder();
            for (byte b : bytes) {
                sb.append(String.format("%02x", b));
            }
            return sb.toString();
        } catch (Exception e) {
            throw new IllegalStateException("签名计算失败", e);
        }
    }

    @Override
    public boolean queryPaid(String orderNo) {
        // 模拟渠道无外部状态，查单补偿由本地订单表状态决定
        return false;
    }
}
```

### 6.4 订单 Mapper 的幂等 SQL（`mapper/RechargeOrderMapper.java`）

```java
package com.library.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.library.entity.RechargeOrder;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Update;

import java.time.LocalDateTime;

@Mapper
public interface RechargeOrderMapper extends BaseMapper<RechargeOrder> {

    /**
     * 幂等置为已支付。
     * 条件 status = 0 保证并发回调下只有一次能成功，返回 0 表示已被处理过。
     */
    @Update("UPDATE recharge_order SET status = 1, channel_trade_no = #{tradeNo}, "
            + "pay_time = #{payTime}, update_time = NOW() "
            + "WHERE order_no = #{orderNo} AND status = 0 AND is_delete = 0")
    int markPaid(@Param("orderNo") String orderNo,
                 @Param("tradeNo") String tradeNo,
                 @Param("payTime") LocalDateTime payTime);

    /**
     * 关闭超时未支付订单，同样靠条件更新保证只关一次。
     */
    @Update("UPDATE recharge_order SET status = 2, update_time = NOW() "
            + "WHERE order_no = #{orderNo} AND status = 0 AND is_delete = 0")
    int closeOrder(@Param("orderNo") String orderNo);
}
```

### 6.5 充值服务核心（`service/impl/RechargeServiceImpl.java`，节选关键方法）

```java
/** 创建充值订单 */
@Override
@Transactional
public RechargeVO create(BigDecimal amount, Integer channel) {
    Long userId = UserContext.getUserId();

    // 1. 金额必须命中档位白名单，杜绝前端篡改金额
    BigDecimal checked = checkAmount(amount);

    // 2. 渠道必须可用
    PayChannel payChannel = channelFactory.get(channel);

    // 3. 落库，状态待支付
    RechargeOrder order = new RechargeOrder();
    order.setOrderNo(generateOrderNo());
    order.setUserId(userId);
    order.setAmount(checked);
    order.setPayChannel(channel);
    order.setStatus(Constants.RECHARGE_STATUS_UNPAID);
    order.setExpireTime(LocalDateTime.now()
            .plusMinutes(Constants.RECHARGE_EXPIRE_MINUTES));
    order.setCreateTime(LocalDateTime.now());
    order.setUpdateTime(LocalDateTime.now());
    rechargeOrderMapper.insert(order);

    // 4. 调渠道，拿到二维码内容
    String qrContent = payChannel.createPay(order);

    RechargeVO vo = new RechargeVO();
    vo.setOrderNo(order.getOrderNo());
    vo.setAmount(order.getAmount());
    vo.setChannel(channel);
    vo.setQrContent(qrContent);
    vo.setExpireTime(order.getExpireTime());
    vo.setStatus(order.getStatus());
    return vo;
}

/** 处理渠道回调（模拟/支付宝/微信共用同一套后处理） */
@Override
@Transactional
public void handleNotify(Integer channel, Map<String, String> params) {
    PayChannel payChannel = channelFactory.get(channel);

    // 1. 验签：防伪造回调，这一步绝不能省
    if (!payChannel.verifySign(params)) {
        throw new BusinessException("回调签名校验失败");
    }

    String orderNo = params.get("orderNo");
    RechargeOrder order = rechargeOrderMapper.selectOne(
            new LambdaQueryWrapper<RechargeOrder>().eq(RechargeOrder::getOrderNo, orderNo));
    if (order == null) {
        throw new BusinessException("充值订单不存在");
    }

    // 2. 金额比对：以本地订单金额为准，回调金额必须一致
    BigDecimal notifyAmount = new BigDecimal(params.get("amount"));
    if (notifyAmount.compareTo(order.getAmount()) != 0) {
        throw new BusinessException("回调金额与订单金额不一致");
    }

    // 3. 幂等闸门：条件更新，影响行数 0 说明已处理过，直接返回
    LocalDateTime now = LocalDateTime.now();
    int updated = rechargeOrderMapper.markPaid(orderNo, params.get("tradeNo"), now);
    if (updated == 0) {
        return;
    }

    // 4. 加余额 + 写流水（同一事务，两者同生共死）
    userMapper.addBalance(order.getUserId(), order.getAmount());
    User user = userMapper.selectById(order.getUserId());
    paymentFlowMapper.insert(buildFlow(
            order.getUserId(),
            Constants.FLOW_TYPE_RECHARGE,
            order.getId(),
            orderNo,
            Constants.FLOW_DIRECTION_IN,
            order.getAmount(),
            user.getBalance(),
            "账户充值"));
}
```

### 6.6 定时任务（`config/ScheduledTasks.java` 追加）

```java
/** 每分钟关闭超时未支付订单 */
@Scheduled(cron = "0 * * * * ?")
public void closeExpiredRechargeOrders() {
    List<RechargeOrder> expired = rechargeOrderMapper.selectList(
            new LambdaQueryWrapper<RechargeOrder>()
                    .eq(RechargeOrder::getStatus, Constants.RECHARGE_STATUS_UNPAID)
                    .lt(RechargeOrder::getExpireTime, LocalDateTime.now()));
    for (RechargeOrder order : expired) {
        try {
            rechargeOrderMapper.closeOrder(order.getOrderNo());
        } catch (Exception e) {
            log.warn("关闭充值订单失败: {}", order.getOrderNo(), e);
        }
```

## 八、测试用例（答辩演示用）

| 用例 | 操作 | 预期 |
|---|---|---|
| 正常充值 | 充值 50 元 → 确认支付 | 余额 +50，订单已支付，流水一条收入 |
| **重复回调** | 同一订单连续调 10 次回调 | 余额只 +50，流水只有 1 条 |
| **伪造回调** | 手工去掉/改错 sign 调回调 | 返回签名校验失败，余额不变 |
| **金额篡改** | 回调里把 50 改成 500 | 报错「回调金额与订单金额不一致」，余额不变 |
| **金额白名单** | 前端传 amount=0.01 | 报错「充值金额不合法」 |
| 超时关单 | 造一条 expire_time 已过的待支付单 | 定时任务 1 分钟内置为已关闭 |
| **并发回调** | 用 JMeter 并发 20 次回调 | 余额只 +50 |
| 余额完整性 | `SELECT balance FROM user` vs `SUM(流水)` | 两者完全相等 |
| 回调放行 | 不带 token 调 `/recharge/notify/mock` | 正常返回，不被 401 拦截 |

**余额校验 SQL（放进答辩演示）**

```sql
SELECT u.id, u.name, u.balance,
       SUM(CASE WHEN f.direction = 1 THEN f.amount ELSE -f.amount END) AS flow_sum
FROM user u
LEFT JOIN payment_flow f ON f.user_id = u.id
WHERE u.role = 0
GROUP BY u.id, u.name, u.balance
HAVING u.balance <> IFNULL(flow_sum, 0);
```

这条 SQL 查出任何一行，就说明账目有问题。**能跑通这条 SQL 且结果为空，你的资金模块就是可信的。**
