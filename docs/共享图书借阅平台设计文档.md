# 书屿 · 共享图书借阅平台 — 设计文档

> 英文名：BookLoop
> 版本：2.0（押金制 + 到馆核销）
> 基线：图书管理系统 1.0（备份于 `桌面/图书管理系统-1.0版本`）
> 日期：2026-11-01
> 技术栈：Spring Boot 2.7.18 + MyBatis-Plus 3.5.5 + MySQL 8.0 + Vue3 + Element Plus

---

## 一、产品定义

> **共享图书借阅平台。** 用户免费借阅，借书时缴纳等同于书价的押金；按期归还全额退还，逾期从押金扣除，逾期满 30 天或押金扣光视为购买。用户也可直接购买图书。管理员在馆内扫描「副本条码 + 读者证」完成借出与归还核销。

### 1.1 与 1.0 的核心差异

| 维度 | 1.0（旧） | 2.0（新） |
|---|---|---|
| 资金模型 | 预存余额，扣款消费 | **押金担保，原路退还** |
| 逾期处置 | 从余额扣，扣不到转欠费 | **从押金扣，扣光即买断** |
| 图书建模 | 书目 + stock 数字 | **书目 + 副本（每册独立条码）** |
| 借还校验 | 线上点击即生效 | **管理员扫码核销才生效** |
| 商户风险 | 用户没钱就亏 | **押金 = 书价，零风险** |

### 1.2 角色

| 角色 | 能做什么 |
|---|---|
| 读者 | 浏览、预约、申请借阅（付押金）、到馆取书、申请归还、购买、查看记录 |
| 管理员 | 书目与副本管理、借出核销、归还核销、逾期处置、订单退款、读者管理 |

### 1.3 业务参数（全部可配置）

| 参数 | 值 | 配置项 |
|---|---|---|
| 借期 | 30 天 | `library.borrow.days` |
| 逾期费 | 1 元/天 | `library.borrow.overdue-fee-per-day` |
| 买断线 | 逾期满 30 天 | `library.borrow.buyout-overdue-days` |
| 最多借阅册数 | 5 本 | `library.borrow.max-count` |
| 押金 | = 借阅图书定价总和（无上限） | 计算 |
| 扣款上限 | min(逾期费 + 破损赔偿, 押金) | 代码约束 |
| 预约保留 | 5 天 | `library.reserve.valid-days` |

## 二、数据模型

### 2.1 实体关系

```
book (书目)  1 ──── N  book_item (副本)
                          │
                          │ 1
                          │
                          N
user (读者)  1 ──── N  borrow (借阅单) ──── 1  pay_order (押金支付单)
   │
   │ 1
   │
   N
purchase_order (购买单) ──── 1  pay_order (书款支付单)

payment_flow (资金流水)：与 user 关联，记录每一笔收支
```

**关键变化**：借阅记录从「指向书目」改为「指向副本」。这是核销能成立的前提。

### 2.2 新建表：`book_item`（副本）

```sql
DROP TABLE IF EXISTS `book_item`;
CREATE TABLE `book_item` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  `book_id`     BIGINT       NOT NULL COMMENT '所属书目id',
  `barcode`     VARCHAR(32)  NOT NULL COMMENT '副本条码（馆内唯一，贴在书内页）',
  `status`      TINYINT      NOT NULL DEFAULT 0 COMMENT '状态：0在馆 1借出中 2已售出 3已买断 4遗失 5破损 6下架 7已预留',
  `location`    VARCHAR(64)  DEFAULT NULL COMMENT '馆内位置，如 A区-3排-02',
  `remark`      VARCHAR(255) DEFAULT NULL COMMENT '备注',
  `is_delete`   TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除',
  `create_time` DATETIME     DEFAULT NULL COMMENT '入库时间',
  `update_time` DATETIME     DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_barcode` (`barcode`),
  KEY `idx_book_status` (`book_id`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='图书副本表（每册实体书一条记录）';
```

### 2.3 新建表：`pay_order`（支付单）

```sql
DROP TABLE IF EXISTS `pay_order`;
CREATE TABLE `pay_order` (
  `id`            BIGINT        NOT NULL AUTO_INCREMENT COMMENT '主键',

  `biz_id`        BIGINT        DEFAULT NULL COMMENT '关联业务id（borrow.id 或 purchase_order.id）',
  `amount`        DECIMAL(10,2) NOT NULL COMMENT '应付金额',
  `refund_amount` DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '已退金额（累计）',
  `status`        TINYINT       NOT NULL DEFAULT 0 COMMENT '状态：0待支付 1已支付 2已关闭 3已全额退款 4部分退款',
  `channel`       TINYINT       NOT NULL DEFAULT 1 COMMENT '渠道：1支付宝 3模拟',
  `trade_no`      VARCHAR(64)   DEFAULT NULL COMMENT '渠道交易号',
  `pay_time`      DATETIME      DEFAULT NULL COMMENT '支付完成时间',
  `expire_time`   DATETIME      NOT NULL COMMENT '订单失效时间（下单+15分钟）',
  `is_delete`     TINYINT       NOT NULL DEFAULT 0 COMMENT '逻辑删除',
  `create_time`   DATETIME      DEFAULT NULL COMMENT '下单时间',
  `update_time`   DATETIME      DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_order_no` (`order_no`),
  KEY `idx_user_status` (`user_id`, `status`),
  KEY `idx_biz` (`biz_type`, `biz_id`),
  KEY `idx_status_expire` (`status`, `expire_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='支付单表';
```

### 2.4 新建表：`payment_flow`（资金流水）

```sql
DROP TABLE IF EXISTS `payment_flow`;
CREATE TABLE `payment_flow` (
  `id`            BIGINT        NOT NULL AUTO_INCREMENT COMMENT '主键',
  `user_id`       BIGINT        NOT NULL COMMENT '用户id',
  `biz_type`      TINYINT       NOT NULL COMMENT '类型：1押金收入 2书款收入 3押金退还 4逾期扣款 5破损扣款 6买断扣款',
  `biz_id`        BIGINT        DEFAULT NULL COMMENT '关联业务id',
  `biz_no`        VARCHAR(32)   DEFAULT NULL COMMENT '关联单号',
  `direction`     TINYINT       NOT NULL COMMENT '方向：1收入 2支出',
  `amount`        DECIMAL(10,2) NOT NULL COMMENT '金额（正数）',
  `balance_after` DECIMAL(10,2) DEFAULT NULL COMMENT '预留字段，2.0 无账户余额，置 NULL',
  `remark`        VARCHAR(255)  DEFAULT NULL COMMENT '备注',
  `create_time`   DATETIME      DEFAULT NULL COMMENT '发生时间',
  PRIMARY KEY (`id`),
  KEY `idx_user_time` (`user_id`, `create_time`),
  KEY `idx_biz` (`biz_type`, `biz_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='资金流水表（账本，只追加不删改）';
```

> 2.0 没有账户余额，`balance_after` 不再有值。流水表的作用变成：**每一笔押金的进出都有据可查**，用于对账和纠纷处理。

### 2.5 改造表：`borrow`

```sql
ALTER TABLE `borrow`
  ADD COLUMN `item_id` BIGINT DEFAULT NULL COMMENT '副本id' AFTER `book_id`,
  ADD COLUMN `deposit_amount` DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '押金金额' AFTER `deadline_time`,
  ADD COLUMN `refund_amount` DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '已退押金' AFTER `deposit_amount`,
  ADD COLUMN `deduct_amount` DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '已扣押金（逾期+破损）' AFTER `refund_amount`,
  ADD COLUMN `pay_order_no` VARCHAR(32) DEFAULT NULL COMMENT '押金支付单号' AFTER `deduct_amount`,
  ADD COLUMN `verify_time` DATETIME DEFAULT NULL COMMENT '借出核销时间（借期起点）' AFTER `borrow_time`,
  ADD COLUMN `update_time` DATETIME DEFAULT NULL COMMENT '更新时间',
  ADD KEY `idx_item` (`item_id`),
  ADD KEY `idx_pay_order` (`pay_order_no`);
```

**字段说明**

| 字段 | 语义 |
|---|---|
| `borrow_time` | 用户下单支付时间（线上） |
| `verify_time` | **管理员扫码核销时间 = 借期起点**，`deadline_time = verify_time + 30天` |
| `deposit_amount` | 借阅时收的押金（= 该书定价） |
| `deduct_amount` | 累计已扣押金（逾期费 + 破损赔偿） |
| `refund_amount` | 累计已退押金 |
| 不变式 | `deduct_amount + refund_amount ≤ deposit_amount` |

### 2.6 改造表：`book`

```sql
ALTER TABLE `book`
  MODIFY COLUMN `stock` INT NOT NULL DEFAULT 0 COMMENT '在馆副本数（派生值，由 book_item 统计维护）';
```

`stock` 保留但改变语义：不再由借还直接加减，而是 `SELECT COUNT(*) FROM book_item WHERE book_id=? AND status=0` 的结果缓存。每次副本状态变更后同步刷新。

### 2.7 改造表：`user`

```sql
-- 2.0 不再使用余额，字段保留但废弃（避免影响既有代码），后续版本清理
ALTER TABLE `user`
  MODIFY COLUMN `balance` DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '【已废弃】余额，2.0 改用押金制',
  MODIFY COLUMN `punish_end_time` DATETIME DEFAULT NULL COMMENT '【已废弃】惩罚期，2.0 由押金制取代';
```

### 2.8 副本条码规则

```
前缀 B + 6 位零填充序号，如 B000001
由入库时自动生成：SELECT MAX(id)+1 后格式化，或建独立序列表
```

条码需打印贴在书内页，管理员核销时扫码枪输入或手输。

### 2.9 新建表：`user_agreement`（规则同意记录）

```sql
DROP TABLE IF EXISTS `user_agreement`;
CREATE TABLE `user_agreement` (
  `id`            BIGINT      NOT NULL AUTO_INCREMENT COMMENT '主键',
  `user_id`       BIGINT      NOT NULL COMMENT '用户id',
  `agreement_type` TINYINT    NOT NULL COMMENT '类型：1借阅规则 2购买须知 3用户协议',
  `version`       VARCHAR(16) NOT NULL COMMENT '协议版本号，如 2.0',
  `agreed_time`   DATETIME    NOT NULL COMMENT '同意时间',
  `client_ip`     VARCHAR(64) DEFAULT NULL COMMENT '客户端IP（留痕）',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_type_version` (`user_id`, `agreement_type`, `version`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='规则同意记录（知情同意留痕）';
```

> **为什么要有这张表**：弹窗本身不值钱，**留痕才值钱**。发生押金纠纷时，能证明「用户在什么时间、同意的是哪个版本的规则」。协议内容改版后升 `version`，老用户需重新确认，否则新条款对他无效。

## 三、状态机

### 3.1 副本 `book_item.status`

```
                    ┌──────────────┐
     入库 ────────► │ 0 在馆        │
                    └──────┬───────┘
                           │
        借出核销 ┌──────────┼──────────┐ 购买
                ▼          │          ▼
        ┌──────────────┐   │   ┌──────────────┐
        │ 1 借出中      │   │   │ 2 已售出      │ (终态)
        └──────┬───────┘   │   └──────────────┘
               │           │
     归还核销  │           │ 管理员标记
               ▼           ▼
        ┌──────────────┐  ┌──────────────┐
        │ 0 在馆        │  │ 4 遗失        │ (终态)
        └──────────────┘  │ 5 破损        │
                          └──────────────┘
        ┌──────────────┐
        │ 3 已买断      │ (终态，逾期未还)
        └──────────────┘
```

**状态 7「已预留」**：用户下单后、尚未到馆核销时，副本被锁定给这一笔借阅单。多人同时借同一册书时，只有一个能预留成功，其余提示「该册已被他人预留」。预留的副本：
- 借出核销 → 转「1 借出中」
- 超时未取 → 释回「0 在馆」并退款

> 没有这个状态，两个用户同时付了押金却只有一册书，其中一人的押金就悬空了。

**终态**（2 已售出 / 3 已买断 / 4 遗失）：不再回到在馆，库存永久减少。
**5 破损**：可视修复情况由管理员改回在馆，或转 4 遗失。
**6 下架**：管理员手动停用，不参与借阅但保留记录。

### 3.2 借阅单 `borrow.status`

| 值 | 状态 | 说明 |
|---|---|---|
| 0 | **待取书** | 已支付押金，等待到馆核销。**未开始计借期** |
| 1 | **借阅中** | 已核销，`deadline_time` 生效 |
| 2 | **已归还** | 归还核销完成，押金已退（可能扣了逾期费） |
| 3 | **已买断** | 逾期满 30 天或押金扣光，书归用户 |
| 4 | **已取消** | 超时未取书 / 用户取消，押金已退 |

> 与 1.0 的 `0借阅中 1已归还 2逾期转购买 3欠费待结算` 完全不兼容，需同步修改 `Constants`。

### 3.3 支付单 `pay_order.status`

| 值 | 状态 |
|---|---|
| 0 | 待支付 |
| 1 | 已支付 |
| 2 | 已关闭（超时未付 / 用户取消） |
| 3 | 已全额退款 |
| 4 | 部分退款 |

## 四、核心流程

### 4.1 借阅全流程

```
① 读者选书点「借阅」
       ↓
② 校验：册数 ≤ 5、副本在馆、无未完成订单
       ↓
③ 选中一册在馆副本，置为「7 已预留」——**锁定副本，防止他人抢走同一册**
       → 计算押金 = 该书定价，创建 pay_order(待支付) + borrow(待取书)
       ↓
④ 跳支付宝收银台付款
       ↓
⑤ 支付成功 → 回调 → pay_order 置已支付 → borrow 保持「待取书」
       ↓
⑥ 读者到馆，出示借阅单
       ↓
⑦ 管理员扫「副本条码 + 读者证」→ 核销
       ↓
⑧ 校验 5 项 → 通过 → borrow 置「借阅中」，verify_time=now，deadline=+30天
                     → book_item 置「借出中」
       ↓
⑨ 到期前 3 天提醒 → 归还核销 → 算逾期 → 退押金 → 副本回「在馆」
```

### 4.2 借出核销判定条件（5 项，缺一不可）

管理员扫副本条码 + 读者证后，逐项校验：

| # | 校验 | 失败提示 |
|---|---|---|
| 1 | 副本存在且状态 = 在馆 | 「该副本不存在 / 已在借出状态」 |
| 2 | 读者证有效（未禁用） | 「该读者账号已被禁用」 |
| 3 | **存在该读者的待取书借阅单**，且借阅单的书 = 该副本所属书 | 「该读者没有待取书的借阅单」 |
| 4 | 该读者在借册数 < 5 | 「已达借阅上限（5 本）」 |
| 5 | 该书无他人有效的「待借阅」预约（预约优先权） | 「该书已为预约读者保留」 |

> 校验 3 是防「随便拿本书来借」和「拿别人的书来借」的关键。没有这一步，扫码核销就形同虚设。

**通过后同一个事务内**：
```sql
UPDATE borrow SET status=1, verify_time=NOW(), deadline_time=DATE_ADD(NOW(), INTERVAL 30 DAY) WHERE id=? AND status=0;
UPDATE book_item SET status=1 WHERE id=? AND status=0;
```
两条都用条件更新，影响行数为 1 才提交，否则回滚。这是防并发重复核销的闸门。

### 4.3 归还核销判定条件

管理员只需扫**副本条码**（不需读者证，从副本反查借阅单即可）：

| # | 校验 | 失败提示 |
|---|---|---|
| 1 | 副本状态 = 借出中 | 「该副本不在借出状态」 |
| 2 | 能查到对应的借阅中借阅单 | 「未找到借阅记录，请检查条码」 |

**通过后计算应扣金额**：

```java
long overdueDays = max(0, DAYS_BETWEEN(deadline_time, now));
BigDecimal overdueFee = 逾期费单价 × overdueDays;
BigDecimal damageFee  = 管理员填写的破损赔偿（默认 0）;
BigDecimal totalDeduct = min(overdueFee + damageFee, deposit_amount);

BigDecimal refundAmount = deposit_amount - totalDeduct;
```

**然后**：
1. 调支付宝退款 `alipay.trade.refund`，金额 = `refundAmount`
2. 退款成功 → `borrow.status=2`、`deduct_amount=totalDeduct`、`refund_amount=refundAmount`
3. `book_item.status=0`（回在馆）
4. 写流水：退款（direction=2 支出）、逾期扣款（direction=1 收入）
5. 刷新 `book.stock`
6. 触发预约唤醒（通知队列下一位）

> 退款失败时**不能**把副本改回在馆——否则书回来了但钱没退，用户会投诉。顺序必须是「先退款成功，再改状态」，退款失败保持原状态并记录告警。

### 4.4 逾期处置（定时任务，每小时）

```
扫描 borrow.status=1 且 deadline_time < now：

  ① 计算逾期天数
  ② 若 逾期天数 ≥ 30  → 触发买断：
       - 押金全部没收（不退款）
       - borrow.status=3
       - book_item.status=3（已买断）
       - 写流水：买断扣款
  ③ 若 逾期天数 < 30  → 仅记录逾期状态，等待归还
       （不提前扣押金，避免用户还书时算不清）
```

> **为什么不每天扣一点？** 因为押金是整笔冻结的，逐日扣会产生大量碎流水，且用户中途还书时对账复杂。**统一在归还时一次结算，或逾期满 30 天一次没收**，账目最清晰。

> 押金扣光的场景（低价书，如 20 元书逾期 20 天费用即达上限）：归结算时 `totalDeduct = min(费用, 押金)` 已天然封顶，不会扣成负数。若用户在扣光后才还书，退款金额为 0，状态仍为「已归还」。

### 4.5 超时未取书（定时任务，每 10 分钟）

```
扫描 borrow.status=0 且 create_time < now - 2 小时：
  → 自动退款（全额）
  → borrow.status=4（已取消）
  → pay_order 置已退款
  → **副本从「7 已预留」释回「0 在馆」**
  → 刷新 book.stock，唤醒预约队列
```

> 2 小时是「线上支付后多久没来取书就取消」。可配置。

### 4.6 购买流程

```
读者点「购买」→ 校验库存 → 冻结一个副本（status 保持不变，仅加锁）
  → 创建 pay_order(biz_type=2) + purchase_order
  → 跳支付宝付款
  → 回调成功 → book_item.status=2（已售出）
  → 刷新 book.stock
  → 生成购买记录，**无退款**
```

### 4.7 预约流程（沿用 1.0，适配副本层）

```
书全部借出 → 读者预约 → 排队（FIFO）
  → 有副本归还 → 唤醒队首 → status=待借阅，valid_deadline=+5天
  → 5 天内到馆核销 → status=已借阅
  → 逾期未来 → status=已失效，顺延下一位
```

预约针对的是**书目**（不是副本），因为用户不关心拿哪一册。

### 4.8 规则确认（知情同意）

押金、逾期、买断这套规则必须在用户**掏钱之前**讲清楚，否则纠纷时无法举证。

**两层设计**

| 层 | 时机 | 内容 | 频次 |
|---|---|---|---|
| 第一层 | 首次点「借阅」或「购买」 | 完整规则全文 | 每个版本只弹一次 |
| 第二层 | 每次支付确认页 | 本次交易的关键数字 + 一个勾选框 | 每次 |

第二层展示的不是全文，而是**跟这笔交易相关的数字**：

```
本次借阅《三体》
押金 93.00 元（归还后全额退还）
借期 30 天，应还日期 2026-12-01
逾期费 1 元/天；逾期满 30 天或押金扣光视为购买，押金不退

☐ 我已阅读并同意《借阅规则》
```

**接口**

| 接口 | 说明 |
|---|---|
| `GET /agreement/current?type=1` | 获取当前版本号与规则全文（内容存后端，改文案不用发前端） |
| `POST /agreement/agree` | 记录同意（用户id + 类型 + 版本 + 时间 + IP） |
| `GET /agreement/mine` | 查询本人已同意的记录 |

**后端强制校验（关键）**

只靠前端弹窗是可以被绕过的——用户直接调接口就跳过了。必须在业务入口校验：

```java
// BorrowServiceImpl.apply() / PurchaseServiceImpl.buy() 入口处
String currentVersion = agreementService.currentVersion(AGREEMENT_TYPE_BORROW);
if (!agreementService.hasAgreed(userId, AGREEMENT_TYPE_BORROW, currentVersion)) {
    throw new BusinessException("请先阅读并同意《借阅规则》");
}
```

**版本管理**

规则文案改版时升 `version`（如 `2.0` → `2.1`），老用户的同意记录对应旧版本，下次借阅会自动要求重新确认。这样新条款才对他有效。

**规则文案存放**

`resources/agreement/borrow-rule.md`、`purchase-rule.md`，由 `AgreementService` 读取并带上版本号返回。不硬编码在前端，也不塞进数据库。

### 5.3 回调处理（关键）

```
POST /pay/notify/alipay

① 验签：AlipaySignature.rsaCheckV1(params, alipayPublicKey, "UTF-8", "RSA2")
   → 失败：记录日志，返回 "failure"
② 取 out_trade_no（= pay_order.order_no）
③ 查本地订单，不存在 → 返回 "success"（避免无意义重推）
④ 金额比对：params.total_amount 必须等于 pay_order.amount
   → 不等：告警，返回 "failure"
⑤ 幂等闸门：
   UPDATE pay_order SET status=1, trade_no=?, pay_time=NOW()
   WHERE order_no=? AND status=0
   → 影响行数 0：说明已处理，直接返回 "success"
⑥ 同事务内：写流水 + 推进业务状态
   - biz_type=1（押金）→ borrow 保持待取书
   - biz_type=2（书款）→ book_item 置已售出
⑦ 返回纯文本 "success"
```

**必须注意**：

- 接口必须**放行 JWT**：`/pay/notify/**` 加入 `WebConfig` 两个拦截器的 exclude
- 返回**纯文本** `success`，不能是 JSON，否则支付宝判失败并重推 8 次
- 回调地址用内网穿透，**natapp 免费版重启会变域名**，变了要改 `notify-url`

### 5.4 退款规则

```java
AlipayTradeRefundRequest req = new AlipayTradeRefundRequest();
req.setBizContent("{" +
    "\"out_trade_no\":\"" + payOrder.getOrderNo() + "\"," +
    "\"refund_amount\":" + refundAmount + "," +
    "\"out_request_no\":\"" + borrowId + "_R" + seq + "\"," +   // 退款请求号，幂等键
    "\"refund_reason\":\"归还押金\"" +
"}");
```

**`out_request_no` 是退款幂等键**：同一值重复调用，支付宝只退一次。规则：`借阅单id_R序号`。

**累计退款不能超过原交易金额**：本地维护 `pay_order.refund_amount`，每次退款前校验 `refund_amount + 本次 ≤ amount`。

### 5.5 主动查单补偿（定时任务，每 5 分钟）

```
扫描 pay_order.status=0 且 create_time < now - 5 分钟：
  → 调 alipay.trade.query
  → 若返回 TRADE_SUCCESS → 走与回调完全相同的入账逻辑（抽出公共方法）
  → 若返回 TRADE_CLOSED   → 置为已关闭
```

> 回调可能因网络、防火墙、域名变更而丢失。**没有查单补偿，掉单就是资损。**
